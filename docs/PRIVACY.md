# 后续更新的隐私发布规范

用户已明确：**之后的更新必须不包含隐私内容**。过去的低敏目录信息保留在原历史中，不做历史改写或强推；这不构成后续更新的豁免。

## 发布前门禁

在仓库根，用本机已有 Python 执行：

```powershell
# 安装到当前仓库，不改全局 Git；已有不同 hook 时拒绝覆盖。
python scripts/check_privacy.py --install-hooks

# 检查实际暂存区，不能用清理后的工作树代替。
python scripts/check_privacy.py --staged

# 检查这次新增的每个提交及最终快照，不只是最新 HEAD。
git fetch origin
python scripts/check_privacy.py --outgoing origin/main
```

pre-commit 检查暂存区；pre-push 使用 Git 提供的远端旧提交和本地新提交，在发送对象前检查本次更新。远端基线不在本地、扫描失败或有命中时，中止操作；不要绕过检查。

新克隆需要自行安装本地 hook。根 GitHub Actions 同时检查提交快照和本次更新范围，但它发生在上传后，仅作补充。

## 自动检查范围

- Windows、Linux、macOS 的真实用户目录；占位符和环境变量可用。
- 常见 GitHub 访问令牌、私钥、直接写入的密码/API 密钥或长凭据。
- 明显手机号、账号 ID，以及本机配置、登录态、真实名册、原始轨迹/画面、历史备份等私有文件。
- 二进制文件先停止并要求复核，避免归档或非文本内容绕过文本检查。
- 新增提交的完整快照和提交元数据；即使最后一条提交已删掉敏感内容，中间提交仍会阻止推送。

检查只报告文件、行号、类别，不回显命中值。规则使用合成测试验证；许可文本、公开作者署名和明确的协议常量仍需按来源准确保留。

## 人工复核

模式扫描不能替代对内容含义的判断。每次提交和推送还须复核改动、提交说明、配置与日志，尤其是截图、转抄的账号信息、个人联系方式和不能自动识别的凭据。

不能确认可公开的内容先留本地，不提交、不上传；不能为了通过扫描而拆分真实秘密、改变编码或加入假占位标记。原始数据与本机配置继续使用本地数据目录、环境变量和忽略规则。
