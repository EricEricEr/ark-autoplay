# 玩家手动操作采集

玩家直接在 MuMu 窗口操作，无需作业文件、采集队列或预定打法。助手旁路读取游戏截图与 Android 原始输入，不启动 MAA 任务，不导航、点击、补给或接管游戏。仍需选择现有运行库，只复用其中的战斗和结算识别模板。

## 使用

1. 在“任务与设置”选择非 C 盘数据位置，并选择 MuMu 设备与配套运行库。名册可以先获取，没有名册时保持缺失。
2. 先停止所选设备上的自动采集、MAA 和游戏代理作战，由玩家本人进入已登录的游戏。软件不会替你结束其他程序。
3. 点击“采集玩家自己的手动操作（无需作业）”。关卡备注可留空，只表示玩家提供的备注，不被猜填成官方关卡 ID。
4. 点击“开始录制这一局”，随后直接在 MuMu 操作，可从编队或进关开始。助手记录截图、触点及 Android 按键，不监听电脑其他窗口。
5. 观察到战斗及连续真实结算证据后自动结束；若只确认已返回游戏主页，则结束并将胜负保持未知。也可点击“停止录制（保留半局）”，没有固定动作数、总时长或静止拍数限制。
6. 结束后点击“导出手动操作包（含画面）”。原图是输入复核所需的一部分，只交可信维护者，不把游戏原图或真实资料提交公开代码仓库。关闭录制小窗不会结束后台记录，主采集面板也可查看和停止。

与自动采集共用档案和设备互斥，同一档案已有任务时不能同时开始手动录制。外部独立自动程序仍须由玩家先停止；输入来源标记为玩家声明及实际 Android 通道，不能据此鉴定操作者身份。

手动模式的恢复及重试入口仍保持只读录制；要切回自动作业须显式重新导入任务，不会悄悄重放以前的队列。

## 实际保存内容

每局在所选数据根下新建独立目录，旧资料保留：

```text
manual_sessions/<录制ID>/
  session.json           来源、备注、输入设备及坐标范围、计数、结算证据与缺失项
  frames.jsonl           原图索引、请求/接收时间、尺寸、SHA-256及识别证据
  shots/*.png            原始采样截图，属于节拍和事件补拍，不是连续录像
  input_events.jsonl     设备时间、主机接收时间、事件类型/代码/值及原始行
  gestures.jsonl         按实际按下/移动/抬起组装的触点轨迹，不截断长拖动
  roster.json            已提供时保存名册快照，缺失时不补造
```

未抬起、系统丢包或读取中断的轨迹标为不完整，未解析的原始输入行也保留。原始坐标不冒充已校准屏幕坐标，键位不自动翻译成技能或干员动作。游戏离开前台、输入读取失败或写盘失败时停止记录并保留已写内容，不操纵游戏恢复。

## 转换与训练边界

原始输入是真实观测，目前没有自动提供“部署哪个干员、哪个格子、朝向、使用哪个技能”的可靠标签，也没有完整结构化 BattleState。`semantic_actions` 保持缺失，`policy_imitation_ready` 为 false；不生成虚构作业，不用现有作业表替代玩家操作。

设备时间与主机接收时间分别保存，截图请求和接收也分别计时。帧与输入的关联明确标为接收时间近似，不能称为精确的动作前状态。原件可供复核、补充标注及后续像素/控制轨道整理，不能直接当作现有实体策略模型的完整模仿标签。

已有离线转换入口支持手动资料：

```powershell
uv run python -m bridge.convert_episodes --data-root "<自选数据根>" --out "<非C盘新输出目录>"
```

仅有手动资料时输出 `manual_input_samples.jsonl`、原图和事件副本、质量报告与哈希清单。样本保留原始事件及近似前后帧引用，`tactical_action` 为 null，`existing_policy_imitation_eligible` 为 false。混有自动作业时，手动结果单列于 `manual/` 下，不混成专家策略样本。未完成、缺图、哈希变化或计数不符的记录单列拒收原因，原件不删除。

专用导出包含原图。通用导出不勾选图像时，清单标记 `manual_images_omitted`，不能将缺图包称为完整手动训练材料。软件不自动上传数据。

本机已只读确认 MuMu 提供输入设备读取通道；输入解析、只读录制循环、结算、导出和转换使用合成样例验证。没有将自动作业轨迹称为真实玩家手动整局验收。
