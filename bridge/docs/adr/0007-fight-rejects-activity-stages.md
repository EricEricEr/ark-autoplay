# ADR-0007：`Fight` 不接受活动关——导航载体与队列筛选的真实约束

- 状态：**已确认，待解决**
- 触发：真机批量复验（2026-10-10）
- 关联：ADR-0006（判据纠错）、`nav_maa.navigate_only`、`gen_queue`

## 现象

用修正判据生成的 3000 条队列跑批量，前 5 局结果：

```
[job 47981] a001_01 (GT-1)   导航失败: append_task(Fight, nav_only=True) 返回 0
[job 86443] a001_01 (GT-1)   同上
[job 73677] camp_01 (乌萨斯)  同上
[job 73809] camp_01 (乌萨斯)  同上
[job 24537] pro_a_1 (PR-A-1)  ✓ 已导航到准备界面 → 任务链完成 → ok 1/5
```

**`wait_idle` 修复验证通过**（不再秒退，能跑到完成），但 **4/5 因 `Fight` 拒收关卡名而失败**。

## 两个独立的约束（必须分清）

### 约束 A：`Fight` 只接受"它认识的"关卡名

`StageNavigationTask::set_stage_name` 的两条路径：
1. task 表直接命中（如 `1-7`、`SR-5`、`PR-A-1`）；
2. 或匹配 `^([A-Za-z]{0,3})(\d{1,2})-(\d{1,2})(?:-?(\w+))*$` **且**存在 `Episode{N}`。

实测队列 3000 条中 `Fight` 可接受率：

| 关卡前缀 | 可接受 | |
|---|---|---|
| `main` 主线 | 457/457 | **100%** |
| `tough` 高难 | 164/164 | **100%** |
| `hard` 高难 | 44/44 | **100%** |
| `sub` 支线 | 96/96 | **100%** |
| `camp` 剿灭 | 0/72 | **0%** |
| `act33side` 等活动 | 0/57 … | **0%** |
| `wk` 物资 | 0/54 | **0%** |
| **合计** | **761/3000** | **25.4%** |

即：**`Fight` 只能打主线/高难/支线，打不了活动关、剿灭、物资筹备。**

### 约束 B：`Copilot` 能处理，但它自己不导航

`Copilot` 的 `navigate_to_stage` **无白名单、无章节要求**，纯 OCR 在地图上
滑动找关（ADR-0006 已证），但它**没有"从主页进入章节地图"的章节寻路**——
在主页会卡死（ADR-0004/0005 详述）。

**所以两条路都不完整**：

| | 章节寻路 | 关卡白名单 | 能否处理活动关 |
|---|---|---|---|
| `Fight` | ✅ `Episode{N}` | ❌ 受限（见上表） | ❌ |
| `Copilot` 自带 | ❌ 无 | ✅ 无限制 | ✅ |

我们目前的方案（`Fight(nav_only)` 导航 + `Copilot` 执行）**只能覆盖 25.4% 的队列**。

## 约束 C（新发现的数据质量问题）

数据集的 `code` 字段有 **54 个关卡是中文而非代号**：

| 类型 | 数量 | 样例 |
|---|---|---|
| CAMPAIGN 剿灭 | 36 | `camp_01` → `code='乌萨斯'`（应为剿灭关卡名） |
| ACTIVITY | 16 | `act1vautochess_m01` → `code='新手模式'` |
| GUIDE | 2 | `guide_01` → `code='???'` |

这些 `code` 直接当关卡名下发必然失败。**队列需按"code 是 ASCII 代号"过滤。**

## 候选方案（待裁决）

### 方案 A：给 `Fight` 补章节寻路能力（扩展 patch 0002）

在补丁里让 `nav_only` 模式支持**已知章节**的显式寻路，绕过 `Episode{N}` 限制。

- 优：复用 patch 机制（已验证）；对上游纯新增。
- 劣：活动关的"章节"在游戏内是活动地图，需要额外的进入逻辑，不是简单放开正则。

### 方案 B：自建"进入章节地图"的前置步骤

用 `StartUp` 到主页 + 固定点位点"终端→曲谱→活动卡"，再交 `Copilot` 自带导航。

- 优：无需改 MAA；`Copilot` 的 OCR 导航本身已能处理活动关。
- 劣：**正是 ADR-0002 废弃的自建几何导航**，需逐活动标定，不可扩展。

### 方案 C：队列只收 `Fight` 可接受的关卡（**当前最务实**）

按 `fight_accepts` 过滤队列，接受"只能打主线/高难/支线"这一现实。

- 优：立刻可用；数据质量可控；覆盖 761 条（当前队列）/ 全量约 8,440 条。
- 劣：放弃活动关（占数据集 71%）。

### 方案 D：先用方案 C 跑通全链路，再攻活动关

分阶段：先让主线/高难/支线稳定产出数据（训练可用），活动关作为后续增量。

## 建议（建议，待裁决）

**方案 D**：先用 `fight_accepts` 过滤队列（立刻能跑），把主线/高难/支线的
数据工厂跑稳、产出训练数据；活动关覆盖率作为独立课题后续解决。
理由：训练数据不需要覆盖全部关卡，先拿到**干净可信**的一批更重要。

## 复验证据（本次）

- `wait_idle` 修复**有效**：批量从"ok 0/20 秒退"变为"能跑到完成"；
- `PR-A-1`（物资筹备 PR 系列）导航成功、4 个 CopilotAction、
  4 条 BattleState（`has_costs/has_kills` 均 True）→ 全链路可用；
- 失败 4 局全部是 `Fight` 拒收关卡名，**与 wait_idle 无关**。
