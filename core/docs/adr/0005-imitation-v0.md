# ADR-0005：模仿学习 v0（无战场状态下的诚实降级）

- 状态：已接受（2026-10-09）
- 范围：`src/ark_core/training/{imitation_data,imitate,run}.py`、`src/ark_core/models/track_a/policy.py`、`src/ark_core/protocol/action.py`、`configs/imitation_v0.yaml`、`tests/unit/test_imitation.py`
- 数据版本：`77.6.0+a550f5e+ak_dataset_v0.1`

## 背景

方案 §8 的目标是 ``P(a_t | state_t)``：模型看到**当前战场状态**（费用、敌人位置、干员
血量技力）决定下一步。但实测确认：**重放过程未落盘任何战场数值状态**——

| 数据 | 动作 | 动作时间戳 | 战场数值状态 |
|---|---|---|---|
| 离线作业 episodes（40,269 条） | ✅ | ❌ | ❌ |
| 真机 bundle（5 条） | ✅ | ✅ | ❌（只有截图） |

而状态**无法离线补回**（重放时未记录即永久缺失，见 STATUS.md §5）。
故行为克隆缺少输入，训练无法按方案原形态启动。

## 决策

**先训练一个明确降级、但形状正确、链路完整的目标**：

```
P(a_t | 关卡静态特征, 编队, a_<t)
```

即用「关卡特征 + 编队 + 动作历史」作为 ``state_t`` 的**代理**。命名与文档一律标注
``v0`` 与"降级"，**不得**对外表述为"自主作战"或"零样本通关"。

### 为什么值得做（不是镀金）

1. **把张量形状与训练链路钉死**：数据管线 → collate → 前向 → 损失 → 掩码 → checkpoint
   全链路真机跑通后，状态感知层就绪时只需**向实体集注入新 token 类型与通道**，
   编码器 / 指针头 / 训练循环均无需重写。
2. **产出可比较的基线**：后续任何改进（含状态注入）都能与此 v0 在同一切分上对比。
3. **量化"状态缺失"的代价**：v0 在真·零样本留出上的分数，正是"不看战场能走多远"
   的实测上界。这个数字本身就是有价值的结论。

### 任务与输出头

每步四个头（与 RFC-0001 的动作空间对齐）：

| 头 | 取值域 | 损失掩码 |
|---|---|---|
| `type` | deploy / skill / retreat / speed / bullet_time | 全部有效步 |
| `target` | 指针：UNK ｜ 全局装置·类别词表 ｜ 编队槽位 | 全部有效步 |
| `cell` | 指针：关卡格子 | **仅 deploy** |
| `dir` | Right / Down / Left / Up / None | **仅 deploy 且 dir ≠ None** |

**为何 cell/dir 加掩码**：其余动作类型无此二项语义。若一并计入（目标恒为 0），
会用恒定噪声稀释梯度，显著拖慢 type 学习——这是训练早期实测到的。

### 编号写法的关键约束

**指针索引布局**（``imitation_data`` 与 ``policy`` 必须严格一致）：

```
[0]                              UNK
[1, 1+vocab)                     全局装置 / 类别 token
[1+vocab, 1+vocab+MAX_SQUAD)     编队槽位
```

模型输出维度 = ``1 + vocab_size + MAX_SQUAD``；编队 padding 槽的 logits 置 ``-inf``。

### 编码表放 protocol 层

``ACTION_TYPES`` / ``DIRECTIONS`` / ``DIR_ALIASES`` / ``GRID_CHANNELS`` 移到
``protocol/action.py``。理由有二：

1. **单一事实来源**——data / model / train 三方必须一致，散落会漂移；
2. **分层方向**——避免 ``models`` → ``training`` 的反向依赖（正确方向是
   ``protocol ← models ← training``）。

**顺序是已发布契约**：变更会让已训练 checkpoint 的权重错位，故只能追加、不得重排。

### 划分纪律

按**关卡家族**留出（方案 §12 最高准则，严禁按对局随机划分）。v0 的 holdout：
``act33side``、``act27side``、``main_13``（整族留出，训练时完全不出现其关卡）。

词表**只从训练家族构建**（``build_vocab``），再套用到 holdout，避免词表层面的泄漏。

### 资源上限

| 上限 | 值 | 依据 |
|---|---|---|
| `MAX_CELLS` | 400 | 实测 2459 关中 99.5% ≤400（最大 1600） |
| `MAX_SPAWNS` | 400 | 实测中位 38、最大 1393；>400 仅 30 关 |
| `MAX_SQUAD` | 16 | 编队上限（实测最大 12 槽） |
| `MAX_ACTIONS` | 128 | 实测 p95 = 27、最大 122 |

超限整局**丢弃并计数**，不静默截断（截断会丢地形且不留痕）。
``MAX_SPAWNS`` 从初版 200 放宽到 400：实测可多保留约 2,300 局，代价仅是注意力
序列变长；被丢弃者集中在 ``camp``（剿灭）与 ``*multi``（多连战）等特殊玩法。

## 实测结果

数据集构建（全量）：

```
扫描 40,269 局 → 保留 38,526 局（95.7%）
词表 134（全局装置/类别 token，只从训练家族统计）
丢弃：no_squad 1255 / too_many_spawns 436 / too_many_cells 38 / too_many_actions 14
deploy：干员 188,783 / 非干员（装置·类别）75,987
目标落 UNK：73,388（其中干员不在编队的约占 6.1%，见下）
```

**关于 UNK**：采样诊断显示干员目标 93.9% 命中本局编队。未命中的 6.1% 主要是
**召唤物**（Mon3tr 312、令 276）与同名异格——即作业作者的 deploy 目标本身不在编队里。
这是**真实数据分布**，不是管线缺陷，故保留并计数而非"修正"。

## 后果

- **正**：训练链路首次端到端跑通（数据→GPU 前向→损失→掩码→checkpoint）；
  指标可复现；为状态注入预留了清晰的扩展点（加实体类型即可）。
- **负 / 必须如实声明**：
  - 本 v0 **不具备自主作战能力**——它不知道场上发生什么，只能"照着见过的图背出
    该下谁、下在哪"；
  - 它在 holdout 上的分数**不能**解读为"零样本通关率"（通关需要真实执行与胜负判定，
    本 v0 只做动作序列的离线预测）；
  - ``avg_prefix`` / ``exact_match`` 偏低是**任务本身**的性质（同一张图有多种正确打法，
    严格序列匹配会低估），不是训练失败的证据。
- **后续**：状态感知层就绪后另立 ADR 记录 v1（真实 ``P(a_t | state_t)``），
  并与此 v0 在同一切分上对比，量化状态带来的增益。
